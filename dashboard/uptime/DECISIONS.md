# Uptime checker decision trail

The design contract is the architect synthesis: the C3 base with grafts G1 to G7, P, B and S. This file
records where the build deviated from that contract or settled something it left open. Each row says why.

| Unit | Decision | Why |
| --- | --- | --- |
| 0 | Branch `uptime/architect` fast-forwarded to `origin/main` before any commit. | The branch had no commits of its own. Building on stale main would grow the merge cost. |
| 1 | `dashboard/uptime` is its own Cargo workspace that path-depends on `ployz-core`. | The checker is AGPL, like the dashboard. Core is Apache. A separate workspace keeps core's lockfile and CI untouched, and it can still reuse core's domain types. |
| 1 | `ployz_core::check_output_line` is now public, and `Detail::new` uses it. | Error details get cut the same way as health-check output, from one function, with no copied rule. |
| 1 | With no other live region, a routine failure stays Reachable and returns `Nothing`. | The sketch dispatched an empty confirm round and expired it back. The outcome is the same with one less state. |
| 1 | The confirm rule is "the quorum fails". The "fails outnumber passes" clause is gone. | A mutation test showed the clause could never decide anything. A round is the trigger plus one confirm per missing vote, so two failing regions always outnumber the passes. Rejection fires once every confirm is in, which is the only point the quorum can become unreachable. |
| 1 | A recheck round ends at the first Fail. Otherwise it waits for every probe or its deadline, and judges what it saw. | A Fail already means the round can't pass. Waiting for the rest would only delay the next round. |
| 1 | With fewer live regions than the quorum, a recheck round still goes out but can't pass. | The evidence still gets stored, and one vantage point never closes what two opened. |
| 1 | `EvidenceItem.status` is `Option<u16>`, and rounds use `Vec`, not `SmallVec`. | A failed or declined probe has no status. Rounds hold at most 3 probes, so a dependency doesn't earn its place. |
| 1 | `Ctx` carries the `CheckId`. | Probe keys need it, and the detector holds no check of its own. |
| 1 | serde on the domain types is deferred to the unit that serializes them. | No unit-1 code needs it. |
| 2 | The tables live in `dashboard/src/modules/uptime/tables.ts`, re-exported from `src/db/schema.ts`, and the migration is generated by `pnpm db:generate`, with the attach calls appended by hand. | It is how every other module ships a table, so the one migrate step covers the checker too. |
| 2 | The fenced statements live in `src/modules/uptime/incident-fence.ts`. The Rust open and close are kept there verbatim, and the CRUD edit is a Drizzle `sql` builder. | The Postgres test proves the fences on the exact text Rust will run, and the CRUD unit reuses the edit statement instead of retyping it. |
| 2 | `changeNameSources.uptime_check` waits for unit 9. | Its key type comes from the registered collections, and the ownership test does not demand it yet. Unit 9 must check that the ownership test's key matching accepts the composite FK. |
| 2 | drizzle-kit drops the explicit `NOT NULL` on primary-key columns and orders the work as tables, indexes, FKs, then attaches. | A primary key implies `NOT NULL`, and the end state matches the contract. |
| 3 | The error class comes from a local `classify` in `agent/probe.rs` that walks the source chain like ployzd's `unreachable_class`, and also maps io `TimedOut`. The sketch's `HttpCheckError::from_error_chain` was not added to core. | This unit may only touch `dashboard/uptime`. ployzd's function is private and takes a `reqwest::Error`. Follow-up: move the walk into core as `from_error_chain` and have ployzd call it. |
| 3 | `Prober::probe(&Job, started_at: UnixMs)` takes the start time instead of a `&ServerClock`. | The corrected clock belongs to the agent loop unit. The prober only needs one reading, so the caller passes it. |
| 3 | The sketch's `is_probeable(ip, allow_ipv6)` is split in two. `is_global` vets every answer, both families. A separate dialable step drops IPv6 while `allow_ipv6` is off. A target left with no dialable IPv4 address is `NotProbed(PrivateAddress)`. | An IPv6 answer we won't dial can still be a rebinding tell, so it is vetted anyway. Reusing `PrivateAddress` for "nothing we may dial" matches what that variant's doc already says, and needs no new variant. |
| 3 | Whole blocks are refused instead of having their embedded IPv4 decoded: `2001::/23` (Teredo, benchmarking, ORCHID), `2002::/16` (6to4) and `192.0.0.0/24`. IPv6 must sit in `2000::/3`, which also refuses `64:ff9b:1::/48`. Only NAT64 `64:ff9b::/96` is judged by its embedded IPv4 address. | 6to4 is deprecated (RFC 7526) and Teredo relays are uncontrolled, so no real origin needs them. NAT64 is how a DNS64 agent network reaches IPv4 origins, so it has to work, and only for public IPv4. |
| 3 | Answers are canonicalized, sorted and deduped before `address % count`. | Resolver order varies by agent and by query. Sorting makes control's rotation index name the same address everywhere. |
| 3 | Production DNS is the system resolver through `tokio::net::lookup_host`, behind a `Resolve` trait. | hickory isn't in core's lockfile. A DNS timeout returns on time, but the blocking `getaddrinfo` thread runs on to completion. Swap in hickory if that ever matters at volume. |
| 3 | `Target`, `Scheme`, `Host` and `Job` are added to `domain.rs` without `Target::parse`. | URL parsing belongs to the feed unit, which reads `uptime_check.url`. Tests build targets with struct literals so they can use ephemeral ports. |
| 3 | `Prober::new` returns `Result<_, rustls::Error>`. TLS uses an explicit ring provider with no `install_default`, and ALPN offers only `http/1.1`. | Choosing rustls's protocol versions is fallible. A process-wide default provider would be global state the agent doesn't need. |
| 3 | `ttfb_ms` is the Request phase alone, from the end of the handshake to the head. `total_ms` covers the whole probe. | Each phase field then measures one phase, and they add up to roughly the total. |
| 3 | `header_limit` is clamped to at least 8192 bytes. | hyper panics on a smaller `max_buf_size`. |
| 3 | When the connection errors after it has already handed over the head, the head wins. | A server that sends the head and closes without TLS close_notify is common with `Connection: close`. hyper reads the head and the abrupt EOF in one poll, so the trusted-TLS test failed with `Unreachable` until this was fixed. |
| 3 | Loopback is permitted only by a `#[cfg(test)]` field `Prober::loopback_ok`, read only by a `#[cfg(test)]` branch in `vetted`. | Release builds have no field, no branch and no setter, so no config or input can turn it on. Tests that check the refusal set it to false. |
| 3 | hyper is pinned to 1.11.0, core's version, instead of the 1.12.0 already in the lock. cc, powerfmt and zeroize are held at core's versions. | Under the 7-day minimum release age, hyper 1.12.0 (2026-10-06) and those transitive releases were too new. |
