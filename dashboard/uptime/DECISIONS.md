# Uptime checker decision trail

The design contract is the architect synthesis: the C3 base with grafts G1 to G7, P, B and S. This file
records where the build deviated from that contract or settled something it left open. Each row says why.

| Unit | Decision | Why |
| --- | --- | --- |
| 0 | Branch `uptime/architect` fast-forwarded to `origin/main` before any commit. | The branch had no commits of its own. Building on stale main would grow the merge cost. |
| 1 | `dashboard/uptime` is its own Cargo workspace that path-depends on `ployz-core`. | The checker is AGPL, like the dashboard. Core is Apache. A separate workspace keeps core's lockfile and CI untouched, and it can still reuse core's domain types. |
| 1 | `ployz_core::check_output_line` is now public, and `Detail::new` uses it. | Error details get cut the same way as health-check output, from one function, with no copied rule. |
| 1 | With no other live region, a routine failure stays Reachable and returns `Nothing`. | The sketch dispatched an empty confirm round and expired it back. The outcome is the same with one less state. |
| 1 | The confirm rule is "the quorum fails". The "fails outnumber passes" clause is gone. | A mutation test showed the clause could never decide anything. A round is the trigger plus one confirm per missing vote, so two failing regions always outnumber the passes. Rejection fires once every confirm is in, which is the only point the quorum can become unreachable. |
| 1 | A recheck round ends at the first Fail. Otherwise it waits for every probe or its deadline, and judges what it saw. | A Fail already means the round can't pass. Waiting for the rest would only delay the next round. |
| 1 | With fewer live regions than the quorum, a recheck round still goes out but can't pass. | The evidence still gets stored, and one vantage point never closes what two opened. |
| 1 | `EvidenceItem.status` is `Option<u16>`, and rounds use `Vec`, not `SmallVec`. | A failed or declined probe has no status. Rounds hold at most 3 probes, so a dependency doesn't earn its place. |
| 1 | `Ctx` carries the `CheckId`. | Probe keys need it, and the detector holds no check of its own. |
| 1 | serde on the domain types is deferred to the unit that serializes them. | No unit-1 code needs it. |
| 2 | The tables live in `dashboard/src/modules/uptime/tables.ts`, re-exported from `src/db/schema.ts`, and the migration is generated by `pnpm db:generate`, with the attach calls appended by hand. | It is how every other module ships a table, so the one migrate step covers the checker too. |
| 2 | The fenced statements live in `src/modules/uptime/incident-fence.ts`. The Rust open and close are kept there verbatim, and the CRUD edit is a Drizzle `sql` builder. | The Postgres test proves the fences on the exact text Rust will run, and the CRUD unit reuses the edit statement instead of retyping it. |
| 2 | `changeNameSources.uptime_check` waits for unit 9. | Its key type comes from the registered collections, and the ownership test does not demand it yet. Unit 9 must check that the ownership test's key matching accepts the composite FK. |
| 2 | drizzle-kit drops the explicit `NOT NULL` on primary-key columns and orders the work as tables, indexes, FKs, then attaches. | A primary key implies `NOT NULL`, and the end state matches the contract. |
| 3 | The error class comes from a local `classify` in `agent/probe.rs` that walks the source chain like ployzd's `unreachable_class`, and also maps io `TimedOut`. The sketch's `HttpCheckError::from_error_chain` was not added to core. | This unit may only touch `dashboard/uptime`. ployzd's function is private and takes a `reqwest::Error`. Follow-up: move the walk into core as `from_error_chain` and have ployzd call it. |
| 3 | `Prober::probe(&Job, started_at: UnixMs)` takes the start time instead of a `&ServerClock`. | The corrected clock belongs to the agent loop unit. The prober only needs one reading, so the caller passes it. |
| 3 | The sketch's `is_probeable(ip, allow_ipv6)` is split in two. `is_global` vets every answer, both families. A separate dialable step drops IPv6 while `allow_ipv6` is off. A target left with no dialable IPv4 address is `NotProbed(PrivateAddress)`. | An IPv6 answer we won't dial can still be a rebinding tell, so it is vetted anyway. Reusing `PrivateAddress` for "nothing we may dial" matches what that variant's doc already says, and needs no new variant. |
| 3 | Whole blocks are refused instead of having their embedded IPv4 decoded: `2001::/23` (Teredo, benchmarking, ORCHID), `2002::/16` (6to4) and `192.0.0.0/24`. IPv6 must sit in `2000::/3`, which also refuses `64:ff9b:1::/48`. Only NAT64 `64:ff9b::/96` is judged by its embedded IPv4 address. | 6to4 is deprecated (RFC 7526) and Teredo relays are uncontrolled, so no real origin needs them. NAT64 is how a DNS64 agent network reaches IPv4 origins, so it has to work, and only for public IPv4. |
| 3 | Answers are canonicalized, sorted and deduped before `address % count`. | Resolver order varies by agent and by query. Sorting makes control's rotation index name the same address everywhere. |
| 3 | Production DNS is the system resolver through `tokio::net::lookup_host`, behind a `Resolve` trait. | hickory isn't in core's lockfile. A DNS timeout returns on time, but the blocking `getaddrinfo` thread runs on to completion. Swap in hickory if that ever matters at volume. |
| 3 | `Target`, `Scheme`, `Host` and `Job` are added to `domain.rs` without `Target::parse`. | URL parsing belongs to the feed unit, which reads `uptime_check.url`. Tests build targets with struct literals so they can use ephemeral ports. |
| 3 | `Prober::new` returns `Result<_, rustls::Error>`. TLS uses an explicit ring provider with no `install_default`, and ALPN offers only `http/1.1`. | Choosing rustls's protocol versions is fallible. A process-wide default provider would be global state the agent doesn't need. |
| 3 | `ttfb_ms` is the Request phase alone, from the end of the handshake to the head. `total_ms` covers the whole probe. | Each phase field then measures one phase, and they add up to roughly the total. |
| 3 | `header_limit` is clamped to at least 8192 bytes. | hyper panics on a smaller `max_buf_size`. |
| 3 | When the connection errors after it has already handed over the head, the head wins. | A server that sends the head and closes without TLS close_notify is common with `Connection: close`. hyper reads the head and the abrupt EOF in one poll, so the trusted-TLS test failed with `Unreachable` until this was fixed. |
| 3 | Loopback is permitted only by a `#[cfg(test)]` field `Prober::loopback_ok`, read only by a `#[cfg(test)]` branch in `vetted`. | Release builds have no field, no branch and no setter, so no config or input can turn it on. Tests that check the refusal set it to false. |
| 3 | hyper is pinned to 1.11.0, core's version, instead of the 1.12.0 already in the lock. cc, powerfmt and zeroize are held at core's versions. | Under the 7-day minimum release age, hyper 1.12.0 (2026-10-06) and those transitive releases were too new. |
| 4 | `pg.rs` and `feed.rs` live in `src/control/`, not at the crate root as the sketch has them. | Only the control plane talks to Postgres. Agents hold no connection, so the module sits beside the detector that consumes it. |
| 4 | `Pg` is one lazily reconnected connection. Every call is `BEGIN; SET LOCAL statement_timeout = '5s', lock_timeout = '1s'; ...; COMMIT`, and only `query_typed` is sent. TLS uses an explicit ring provider and webpki roots, with no `install_default`. | PgBouncer transaction pooling keeps no session state and no named statements, and this matches core's `ployz-store` precedent. A broken client is dropped after the call that saw it, and the next call reconnects. |
| 4 | `PgError` has three kinds. `SchemaNotReady` covers 42P01 and 42703. `Transient` covers errors with no SQLSTATE, classes 08, 40 and 57, 55P03 and 53300. Everything else is `Fatal`. | The caller keeps what it holds and retries on the first two. A retry won't fix the third. |
| 4 | The cursor is taken before the keyset load, and each page is its own short transaction. | Anything committed during the load has an xid at or above the cursor, so the tail replays it. |
| 4 | The keyset load filters `c.enabled` and pages 10,000 rows by `id`, starting from the nil uuid. `parse` also drops disabled rows. | The map holds enabled checks only, as `Check`'s doc says. The SQL filter is the efficient guard. The parse check is what the tail re-read relies on. |
| 4 | Each tail window, and the re-read of the checks it names, runs in one transaction. The cursor advances only after that commits. | A failed window re-reads the same range, so a change made while the connection was down is never skipped. |
| 4 | The contract's `OrgReplaced` is folded into `FeedEvent::Changed { reloaded, gone, replaced_orgs, skipped }`. The re-read is `WHERE c.id = ANY($1) OR c.organization_id = ANY($2)`. | One window becomes one event with one apply order: drop the replaced orgs, drop `gone`, then hold `reloaded`. Two events from one window could be applied half-way. |
| 4 | `CheckRow` has no `enabled` field. A hinted check that comes back disabled, deleted or malformed is listed in `gone`. | The log's ids are hints, and the re-read decides. An illegal held-but-disabled state can't be represented. |
| 4 | An `expired` window becomes a full reload. It takes a fresh cursor and emits `Loaded`. An empty window still advances the cursor. | Retention has pruned rows the cursor still needs, so only a full reload is sound. The tail statement always returns one row, so the idle path costs one round trip. |
| 4 | A malformed row is skipped and never kills the feed. It surfaces in three places. A `tracing::warn!` names the check, the org and the reason. `Snapshot::skipped` or `Changed::skipped` carries it to the caller. If the check was held, it lands in `gone`. | The operator sees it in the logs. The engine can report it, for example as a status on the check. Probing a stale target after an edit made it malformed would be wrong. A column that won't decode at all is `PgError::Fatal`, because that means the schema doesn't match this build, not that one row is bad. |
| 4 | `Target::parse` accepts port 80 or 443, explicit or by default, with either scheme. It rejects `#` explicitly. `Expect::parse` and `Check` are added to `domain.rs`. | The database CHECK allows any port, so this is where the probe's rule is enforced. `https://host:8443/` is the realistic malformed row. `http::Uri` drops fragments silently. |
| 4 | Row validation also checks that `timeout_ms` is within 1000..=30000 and below the interval. | It repeats the database CHECK, so the domain type can be trusted. A row that breaks it is skipped like any other. |
| 4 | Not built here: the `LIMIT 0` readiness probe of `probe_capabilities`. It moves to the engine and main unit. | That unit decides what to do on `SchemaNotReady` at boot. The feed already returns the error. |
| 4 | New dependencies are tokio-postgres 0.7.18 (`with-uuid-1`), tokio-postgres-rustls 0.14.0 and tracing 0.1.44, plus tokio's `rt` feature. The transitive crates are held at core's lock versions, except chacha20 0.10.2 and web-sys 0.3.106. | Core's chacha20 0.10.1 is yanked, and 0.10.2 was published 2026-08-27. web-sys 0.3.106 matches the js-sys and wasm-bindgen that unit 3 locked. Everything new is older than 7 days. |
| 4 | The feed tests start their own postgres:16-alpine through the Docker CLI and apply every `dashboard/drizzle/*/migration.sql` in order. The reconnect test gives the feed its own role and holds the outage open with `CONNECTION LIMIT 0`. | They run the real change-log triggers. With only `pg_terminate_backend`, the client already reads as closed and reconnects at once, so no window fails. A cursor that resets on failure then survived. That was observed by mutation. |
| 5 | `incidents.rs` holds the TS `open` and `observedClose` statements as `OPEN` and `OBSERVED_CLOSE`, identical up to whitespace. `the_statements_match_the_dashboard_copies` reads `../src/modules/uptime/incident-fence.ts` and compares the two after collapsing whitespace. | The dashboard's own Postgres test proves the TS copies. The drift test makes the Rust copies the same statements, so any change has to land in both. |
| 5 | When a statement applies nothing, the writer reads `EXISTS uptime_alert (incident_id, kind)` in the same transaction and reports that as `applied`. | Only this writer records an observed transition, and the outbox row commits with it, so the alert proves the op committed. A retry after a commit whose reply was lost then reports applied instead of making the engine open again. Observed with the `LostCommit` proxy, for both open and close. |
| 5 | A retried `Open` whose incident was already opened and closed elsewhere fails on the incident primary key (23505) and is reported `applied: false` as Fatal. | That needs a second writer to close the incident between the lost reply and the retry. With one control plane that can't happen. Reasoned, not tested. |
| 5 | Evidence JSON uses the camelCase keys of the TS `IncidentEvidence` type: `distinctRegions`, `oneRegion { probes, spacingMs }`, `failedPhase`, `remoteIp`, `status` 0 when there is no response, and ISO-8601 UTC timestamps with milliseconds. The observed `closed_by` is the evidence plus `"kind": "observed"`. The alert payload is `{organizationId, checkId, checkName, url, transition, evidence, at}`. | The dashboard reads these columns through the TS types, not through `schema.sql`'s snake_case comments. Ids go in as strings, because `Uuid` has no serde feature here. |
| 5 | The ISO formatter is hand-rolled with Hinnant's civil_from_days. | It is one function, and a date crate would only serve it. Tested at the epoch, before it, two leap days and a year end. |
| 5 | `IncidentWriter` is one task behind a bounded `mpsc` (10,000), and reports each op as `Written` on an `mpsc::Sender` the engine owns. `submit` never waits, and a closed writer reads as `Full`. | Ops on one check must apply in order, and one task is the simplest order. The engine can't block on Postgres. Either refusal means the engine resyncs, so it needs no second variant. Transient and SchemaNotReady errors retry with backoff from 200 ms to 5 s. Fatal is logged and reported not applied. |
| 5 | The results insert joins the unnest to `uptime_check` on `(id, organization_id)` with `FOR KEY SHARE OF c`, then `ON CONFLICT DO NOTHING`. The sink role needs UPDATE on `uptime_check` for the row lock, besides SELECT and INSERT on `uptime_result`. | Without the join, one result for a check deleted since it was judged fails the whole batch on the foreign key. The lock stops the delete from racing the insert. Without UPDATE the batch is refused with 42501, which `a_refused_batch_is_dropped_and_counted` observes. |
| 5 | The results buffer is a `VecDeque` with a head sequence number. Rows stay until their insert commits. Overflow drops the oldest rows and counts them. A Fatal batch is dropped and counted too. Transient errors retry the same rows with backoff. | A flush settles exactly the rows it sent, even when overflow evicted some of them mid-flight. A Fatal batch would never succeed and would wedge every row behind it. The count is what makes a lost row visible. |
| 5 | NUL characters are stripped from `detail` before insert. | Postgres text can't hold NUL, and one row must not sink its batch. |
| 5 | serde_json is 1.0.151, with tokio-postgres's `with-serde_json-1` feature. | The lock had 1.0.152, published 2026-10-10, which is too new. 1.0.151 (2026-07-20) is core's version. |
| 5 | `column` moved from `feed.rs` to `pg.rs`. | Both the feed and the incident writer decode rows with it. |
| 5 | The Postgres harness moved to `control/test_pg.rs`, shared by the feed, incident and results tests. It adds `Postgres::role`, `cut` and `restore` for held outages, and `LostCommit`, a TCP proxy that forwards one `COMMIT` and closes the connection before the reply. | Three test modules need the same container, migrations and outage tools. `LostCommit` is the only way to get a commit that landed while the client saw an error. |
| 5 | `ProbeKind`, `Phase` and `Verdict` gained `as_str`, `UnixMs` gained `to_system_time`, and `http_error_str` was added. | Both the evidence JSON and the result rows need the column spellings. `error_spellings_match_core` holds `http_error_str` to core's serde spelling. |
| 5 | The control role needs UPDATE on `uptime_check` once, for both writers. | Row locks need it. The fenced open already takes `FOR SHARE`, so the sink's `FOR KEY SHARE` adds no new grant. Unit 7 grants it on the control role. |
