- One core writer persists before publishing changed; startup, intent invalidation, and 60-second tick wake it; wakes coalesce and refreshes never overlap. Refreshes and external DNS mutations have explicit bounded operations and secret-free evidence.
- NATS contracts are ingress endpoint get plus identity-only changed and machine-scoped gateway status get. Machines/operators may read/subscribe; only the controller may serve/write/publish.
- Managed DNS is a peer projection consumer in the existing lease task. Subscribe first, get, re-get on invalidation/reconnect. Current/Retained apply the complete set; Unavailable withdraws; Pending/get errors do nothing. Target enable acquires idempotently; disable performs one retryable final withdraw then idles.
- Managed DNS checkpoint is last successful projection identity plus complete endpoint set, beside Worker issued_at/expires_at. Retry failed applies with existing 5-second-to-1-hour backoff. Renew at issued_at + 2/3 lifetime, visibly replaying the stored set even during Pending/get error. Disabled gets no keepalive.
- Ployz wildcard and custom exact certificates share active-certificate lifecycle/distribution but keep separate issuers. Private material moves only through bounded artifact RPC and local secret stores, never intent/runtime/evidence. Returning gateways synchronize all required certs before fresh publishable status.
- Automatic activation validates durable preconditions before operation creation, then obtains the applicable cert, syncs all currently publishable gateways, and atomically commits the binding with the deploy phase. Initial failure leaves it unattached; replacement preserves old binding on failure. DNS preflight mismatch becomes warning evidence. Renewal failure retains valid material; expiry isolates dependent routes.
- Configuration update is one bounded atomic command. Target disable is rejected while Ployz automatic configuration is selected; automatic configuration change/disable is rejected while Automatic-origin bindings exist.
- Founder/Cloud defaults enable target plus Ployz automatic hostnames without waiting. CLI removes --public-url and exposes explicit choices. Compose requires an explicit automatic label and no public-port selector. Runtime/SDK expose separate non-secret configuration, target allocation/status, projection, active-certificate metadata, binding origin/identity, and per-route TLS availability.
