# Residual Review Findings

Source context: capability backend/runtime architecture slice on branch `feat/idiomatic-crate-boundaries`, reviewed with correctness, maintainability, and testing subagents.

- P1 `crates/ployz-nats/src/coord/rpc.rs`: Internal NATS node RPC is mostly split from public daemon response types, but the legacy `NatsNodeRpcClient::request` bridge still returns `DaemonResponse` for residual edge and forwarding paths. Follow-up should continue retiring raw bridge users until NATS speaks only internal node command/response types and daemon responses are adapted at the `ployzd` edge.
- P2 `crates/ployzd/src/daemon/handlers/deploy.rs`: The deploy handler remains too large and still composes backend infrastructure with workflow policy. This slice moves node deploy runtime composition to capability backends, but deploy still owns NATS lock/client setup, certificate/deploy coordination, orchestration calls, and response shaping. Follow-up should extract a deploy operation service so the handler only maps request resources and responses.
- P2 `crates/ployz-node-runtime/src/lib.rs`: Node runtime is still foundational rather than the owner of daemon component lifetimes. This slice introduces runtime and supervision primitives, but `ployzd` does not yet route gateway, DNS, NATS, cert renewal, image receiver, ZFS transfer listener, or bootstrap peer seed through it. Follow-up should migrate one real long-lived component first, then continue by component class.
