# Confirm Tailcat removal through a protected successor

Tailcat has no centrally enforced Relay Revoke: Cloud disables its current pairing and cancels that generation's sessions immediately, but only endpoint evidence confirms revocation. The existing protected pairing row retains a bounded removal attempt; its successor capability is never an ordinary connection candidate. The Machine clears the expected pairing, atomically replaces its capability, and restarts only the existing helper; Cloud confirms the intended Machine through the successor and observes that pairing is absent before erasing removal credentials. This avoids treating a dead acknowledgement stream or an offline Machine as success, without a controller or helper-control service.

The expected pairing credential prevents a delayed attempt from clearing a new enrollment even when that enrollment uses the previous successor capability. An absent pairing alone never short-circuits rotation. Offline or unknown endpoints retain an unconfirmed attempt and the founding claim; explicit retry performs bounded work. PostgreSQL notifications cancel matching-generation Cloud session scopes across workers, with durable pairing state gating new connections and listener failure closing sessions.

A Tailcat capability grants shared administrative access, so rotation revokes every holder of the old capability; there is no per-user Tailcat revocation. Cloud logout ends Cloud authorization and does not invalidate a separately held direct capability. Independently authorized SSH, workloads, and kernel WireGuard remain independent of pairing removal.
